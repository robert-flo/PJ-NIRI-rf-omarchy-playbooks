## 🎯 Objetivo

Que `gracie` (administración + Omarchy/Hyprland) tenga su propio repositorio **`robert-flo/omarchy-dotfiles`**, gestionado con dotbare como `niri` y `sura`, separado de `niri-dotfiles`. Así sus ajustes de Omarchy se replican en otra PC sin repetir pasos a mano.

## 🛠️ Procedimiento Previsto

Mismo método que [[03.1 - Dotfiles con dotbare|03.1]], ejecutado **como `gracie`**:

```bash
export DOTBARE_DIR="$HOME/.cfg" DOTBARE_TREE="$HOME"

# 1. Snapshot previo (03.3)
sudo btrfs subvolume snapshot -r /home "/home/.snapshots/home-$(date +%F)-pre-omarchy-dotfiles"

# 2. Repositorio bare y archivos curados (lista de la tabla, tras resolver las decisiones)
dotbare finit
dotbare config status.showUntrackedFiles no
dotbare add ~/.config/hypr/hyprland.lua ~/.config/hypr/monitors.lua ~/.config/hypr/herald-os.lua
# ... resto de la lista curada ...

# 3. Auditoría de secretos (03.1, sección 4), commit inicial y publicación
git --git-dir="$HOME/.cfg" --work-tree="$HOME" commit -m "Capture gracie's Omarchy configuration"
gh repo create robert-flo/omarchy-dotfiles --private --source "$HOME/.cfg" --push   # o --public, según la decisión
```

El repo nuevo nace con un commit inicial en `master` (única excepción a "nunca commit directo a `master`"); a partir de ahí, ramas auxiliares + PR como en el resto.

**Restaurar en otra PC** (como `gracie`): `dotbare finit -u https://github.com/robert-flo/omarchy-dotfiles.git`, después el arreglo de refspec/upstream de [[03.1 - Dotfiles con dotbare|03.1, sección 0]] y `hyprctl reload` + `hyprctl configerrors`.
