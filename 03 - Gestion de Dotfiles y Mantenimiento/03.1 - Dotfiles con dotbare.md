# 📦 Gestión de Dotfiles con dotbare

> [!NOTE]
> **Navegación:**
> * Anterior: [[02.4 - Referencias de Temas, Wallpapers y Recursos|Referencias de Temas y Recursos]]
> * Siguiente: [[03.2 - Validacion en Usuario Limpio (Testbench)|Validación en Usuario Limpio (Testbench)]]
> * Posterior: [[03.3 - Snapshots de Home con Btrfs|Snapshots de Home con Btrfs]]
> * Volver a: [[00 - Indice General (MOC)|Índice General]]

Este playbook describe el flujo de trabajo para versionar, auditar y compartir públicamente la configuración completa del escritorio Niri y Clavis utilizando **[dotbare](https://github.com/kazhala/dotbare)** (un gestor interactivo basado en repositorios Git *bare* sobre `$HOME` con soporte de `fzf`).

---

> [!NOTE]
> **Estado en la máquina de referencia:** el repositorio público ya existe: [robert-flo/niri-dotfiles](https://github.com/robert-flo/niri-dotfiles). En una reinstalación **no se repiten las secciones 2–5** (crear y publicar). Basta con clonarlo con `dotbare finit -u` en el usuario de pruebas `sura`, como se describe en [[03.2 - Validacion en Usuario Limpio (Testbench)|Validación en Usuario Limpio]]. Las secciones de creación quedan como referencia.

## 🎯 Por qué dotbare

1. **Sin enlaces simbólicos frágiles:** Los archivos residen directamente en `$HOME` y `~/.config/`, evitando estructuras intermedias que complican la edición.
2. **Repositorio Bare (`~/.cfg`):** El repositorio Git no contiene un directorio de trabajo normal visible, manteniendo el home limpio.
3. **Control granular:** Solo los archivos explícitamente agregados con `dotbare add` son seguidos por Git (`status.showUntrackedFiles=no`).

---

## 1️⃣ Preparación

Instalar `dotbare` desde AUR (depende de `fzf`):

```bash
yay -S --needed dotbare
```

---

## 2️⃣ Inicialización del Repositorio Bare

Ejecutar bajo la identidad del usuario objetivo (ej. `niri`):

```bash
TARGET_USER="${1:-$USER}"
TARGET_HOME="$(getent passwd "$TARGET_USER" | cut -d: -f6)"

sudo -u "$TARGET_USER" env HOME="$TARGET_HOME" DOTBARE_DIR="$TARGET_HOME/.cfg" DOTBARE_TREE="$TARGET_HOME" \
  GIT_CONFIG_PARAMETERS="'init.defaultBranch=master'" bash -c 'cd ~
# Inicializar repositorio bare
dotbare finit -y </dev/null

# Configurar identidad de Git (ajusta con tus datos públicos)
git --git-dir=.cfg config user.name  "Tu Nombre"
git --git-dir=.cfg config user.email "tu_email@ejemplo.com"
'
```

---

## 3️⃣ Lista Curada de Archivos a Trackear

> [!IMPORTANT]
> **Qué trackear:** Archivos de configuración de Niri, Clavis, temas, scripts, configs de aplicaciones y wallpapers seleccionados.
> **Qué EXCLUIR:** Backups `*.bak*`, cachés, estados de sesión (`.local/state`), notas personales de Obsidian, perfiles con credenciales de correo/Thunderbird y salidas generadas de Matugen (salvo aquellas requeridas para validar sintaxis inicial).

```bash
sudo -u "$TARGET_USER" env HOME="$TARGET_HOME" DOTBARE_DIR="$TARGET_HOME/.cfg" DOTBARE_TREE="$TARGET_HOME" bash -c 'cd ~
dotbare add README.md .github/showcase.mp4 \
  .config/niri/config.kdl .config/niri/clavis .config/niri/cursor-theme.kdl .config/niri/obsidian-violet.kdl \
  .config/niri/liquidbird.kdl .config/niri/statindet-animations.kdl .config/niri/statindet-colors.kdl \
  .config/clavis/config.json .config/clavis/matugen/config.toml \
  .local/share/statindet-niri .local/share/fcitx5-matugen-theme .local/share/clavis-fish-theme \
  .config/mpv .config/gtk-3.0/settings.ini .config/gtk-4.0 .config/environment.d \
  .config/fcitx5/conf/classicui.conf .config/fish/config.fish .config/alacritty/alacritty.toml \
  .config/thunderbird/profiles.ini .config/thunderbird/installs.ini \
  .config/thunderbird/*.default-release*/chrome .config/thunderbird/*.default-release*/user.js \
  .config/obsidian/obsidian.json .config/obsidian/user-flags.conf \
  Documents/Notas/.obsidian/appearance.json Documents/Notas/.obsidian/themes Documents/Notas/.obsidian/snippets \
  .local/share/clavis/wallpapers/wallhaven-5y3571.jpg .local/share/clavis/wallpapers/statindet/wallhaven-rq6yqm.jpg
'
```

## 4️⃣ Auditoría Estricta de Secretos (Antes de Compartir)

Antes de hacer público el repositorio o empujar cambios a GitHub, es indispensable escanear en busca de credenciales, claves SSH o tokens:

```bash
sudo -u "$TARGET_USER" bash -c 'cd ~; git --git-dir=.cfg --work-tree=. ls-files -z | xargs -0 rg -n -i -I \
  -e "ghp_[A-Za-z0-9]{20,}" -e "github_pat_" -e "-----BEGIN .*PRIVATE KEY" \
  -e "(password|passwd|secret|api[_-]?key|token)\s*[=:]\s*\S{6,}" -e "@(gmail|outlook|hotmail)\."'
```

*Si la búsqueda arroja cero coincidencias no autorizadas, el árbol está limpio para ser compartido.*

---

## 5️⃣ Commit y Publicación en GitHub

```bash
# 1. Crear el commit inicial
sudo -u "$TARGET_USER" bash -c 'cd ~; git --git-dir=.cfg --work-tree=. commit -m "Initial commit: niri + Clavis desktop configuration"'

# 2. Crear repositorio público en GitHub con GitHub CLI (gh)
gh repo create niri-dotfiles --public --description "niri + Clavis (Quickshell) desktop dotfiles, managed with dotbare"

# 3. Vincular y enviar a la rama principal
sudo -u "$TARGET_USER" bash -c 'cd ~
git --git-dir=.cfg remote add origin https://github.com/<tu_usuario>/niri-dotfiles.git
git --git-dir=.cfg push -u origin master
'
```

## 6️⃣ Flujo de Trabajo Diario

Dentro de la sesión interactiva del usuario:

```bash
# Variables de entorno (recomendado añadirlas a ~/.config/fish/config.fish)
set -gx DOTBARE_DIR "$HOME/.cfg"
set -gx DOTBARE_TREE "$HOME"

# Ver estado interactivo con fzf
dotbare fstat

# Seleccionar archivos para añadir
dotbare fadd

# Crear ramas para cambios experimentales y enviar Pull Requests
dotbare checkout -b mi-ajuste
dotbare commit -m "feat: ajustar curvatura de esquinas"
dotbare push -u origin mi-ajuste
gh pr create --base master --head mi-ajuste
```

## 7️⃣ Script de Post-Instalación en Máquinas Nuevas

Al clonar los dotfiles en otra máquina o usuario (`dotbare finit -u <url>`), ciertos valores del sistema no se almacenan directamente en Git (como claves de GSettings y rutas dinámicas de `$HOME`). Para ello, se emplea el script idempotente `~/.local/bin/niri-dotfiles-postinstall`:

```bash
#!/usr/bin/env bash
set -euo pipefail

echo "==> Ejecutando niri-dotfiles-postinstall..."

# 1. Normalizar rutas a $HOME actual en configuraciones clave
if [ "$USER" != "niri" ]; then
    sed -i "s|/home/niri|$HOME|g" "$HOME/.config/clavis/config.json" 2>/dev/null || true
    sed -i "s|/home/niri|$HOME|g" "$HOME/.config/obsidian/obsidian.json" 2>/dev/null || true
fi

# 2. Aplicar preferencias de GSettings
if command -v gsettings &>/dev/null; then
    gsettings set org.gnome.desktop.interface gtk-theme 'MacTahoe-Dark' || true
    gsettings set org.gnome.desktop.interface icon-theme 'MacTahoe-dark' || true
    gsettings set org.gnome.desktop.interface cursor-theme 'MacTahoe-dark-cursors' || true
    gsettings set org.gnome.desktop.interface cursor-size 24 || true
    gsettings set org.gnome.desktop.interface color-scheme 'prefer-dark' || true
    gsettings set org.gnome.desktop.wm.preferences button-layout 'close,minimize,maximize:' || true
fi

# 3. Habilitar servicios de usuario systemd
if command -v systemctl &>/dev/null; then
    systemctl --user enable clavis-shell.service clavis-clipboard.service 2>/dev/null || true
fi

# 4. Crear directorios de soporte
mkdir -p "$HOME/Pictures/mpv"

# 5. Validar configuración de Niri
if command -v niri &>/dev/null; then
    niri validate -c "$HOME/.config/niri/config.kdl"
fi

echo "✅ Post-instalación finalizada con éxito."
```
