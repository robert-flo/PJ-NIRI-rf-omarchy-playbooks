# 🧪 Validación en Usuario Limpio (Testbench de Portabilidad)

> [!NOTE]
> **Navegación:**
> * Anterior: [[03.1 - Dotfiles con dotbare|Gestión de Dotfiles con dotbare]]
> * Siguiente: [[03.3 - Snapshots de Home con Btrfs|Snapshots de Home con Btrfs]]
> * Volver a: [[00 - Indice General (MOC)|Índice General]]

Este playbook establece una metodología formal para verificar la portabilidad, estabilidad e idempotencia de la configuración en un **usuario de pruebas desechable** (*testbench*). Permite certificar que los dotfiles funcionan correctamente en un entorno limpio sin comprometer la cuenta de uso diario.

---

## 🎯 Objetivo de la Prueba

1. Clonar e inicializar el repositorio público de dotfiles mediante `dotbare finit` en una cuenta sin configuraciones previas.
2. Identificar y resolver problemas comunes de portabilidad:
   - Rutas absolutas hardcodeadas (`/home/<usuario_original>` vs `$HOME`).
   - Enlaces simbólicos rotos o no relativos.
   - Ajustes residentes fuera del control de versiones (GSettings / dconf, servicios systemd de usuario, carpetas vacías).
3. Validar mediante una lista de control interactiva (*QA Checklist*) tanto en consola como en sesión gráfica Wayland.
4. Desmantelar de forma segura el usuario de pruebas sin dejar residuos en el sistema.

---

## 1️⃣ Creación del Usuario de Pruebas (Testbench)

Crear un usuario aislado (ejemplo: `testbench`) con los mismos permisos y grupos requeridos por Niri:

```bash
TEST_USER="testbench"

# 1. Crear usuario con grupos de hardware y wheel
sudo useradd -m -s /bin/bash -G wheel,audio,input,video "$TEST_USER"

# 2. Asignar contraseña temporal
echo "Asigna la contraseña para el usuario de pruebas:"
sudo passwd "$TEST_USER"

# 3. Permisos de sudo para automatización
sudo bash -c "cat <<EOF > /etc/sudoers.d/04_${TEST_USER}
${TEST_USER} ALL=(ALL) NOPASSWD: ALL
Defaults:${TEST_USER} verifypw = any
EOF
chmod 0440 /etc/sudoers.d/04_${TEST_USER}
visudo -c
"

# 4. Habilitar systemd linger para pruebas de servicios de fondo
sudo loginctl enable-linger "$TEST_USER"
```

---

## 2️⃣ Despliegue de Dotfiles con `dotbare`

Simular la experiencia de un usuario nuevo clonando directamente desde el repositorio Git remoto:

```bash
REPO_URL="https://github.com/<tu_usuario>/niri-dotfiles.git"
TEST_HOME="$(getent passwd "$TEST_USER" | cut -d: -f6)"
TEST_UID="$(id -u "$TEST_USER")"

sudo -u "$TEST_USER" env HOME="$TEST_HOME" DOTBARE_DIR="$TEST_HOME/.cfg" DOTBARE_TREE="$TEST_HOME" bash -c "
cd ~
dotbare finit -y -u '$REPO_URL' </dev/null
"
```

> [!NOTE]
> `dotbare` migrará automáticamente cualquier conflicto inicial generado por los archivos plantilla de `/etc/skel` a la carpeta `~/.local/share/dotbare/`.

---

## 3️⃣ Ejecución del Script de Post-Instalación

Ejecutar el script de normalización para ajustar rutas dinámicas, GSettings y demonios:

```bash
sudo -u "$TEST_USER" env HOME="$TEST_HOME" XDG_RUNTIME_DIR="/run/user/$TEST_UID" bash -c "
~/.local/bin/niri-dotfiles-postinstall
"
```

## 4️⃣ Diagnóstico Automatizado de Consola

Verificar la integridad de los componentes antes de iniciar sesión gráfica:

| Prueba | Comando | Salida Esperada |
|---|---|---|
| **Sintaxis de Niri** | `sudo -u $TEST_USER niri validate -c ~/.config/niri/config.kdl` | `INFO niri: config is valid` |
| **GSettings (Tema GTK)** | `sudo -u $TEST_USER gsettings get org.gnome.desktop.interface gtk-theme` | `'MacTahoe-Dark'` |
| **GSettings (Botones)** | `sudo -u $TEST_USER gsettings get org.gnome.desktop.wm.preferences button-layout` | `'close,minimize,maximize:'` |
| **Generación Matugen** | `ls -la $TEST_HOME/.local/share/fcitx5/themes/Matugen/` | Archivos SVG y PNG generados correctamente |
| **Symlinks GTK4** | `readlink $TEST_HOME/.config/gtk-4.0/gtk.css` | Enlace relativo válido a `gtk-Dark.css` |

Comprobar que no existan rutas residuales del usuario creador:
```bash
sudo -u "$TEST_USER" bash -c "
cd ~
git --git-dir=.cfg ls-files -z | xargs -0 grep -Hn '/home/' | grep -v '$TEST_USER' || echo '✅ Árbol 100% portable'
"
```

## 5️⃣ Lista de Verificación Visual (QA Checklist en Sesión Gráfica)

Iniciar sesión en **SDDM** seleccionando el usuario `testbench` y el escritorio **Niri**:

> [!CHECKLIST]
> - [ ] **Clavis Shell:** La barra superior, reloj, widgets y panel lateral aparecen con fluidez.
> - [ ] **Wallpaper:** Se renderiza el fondo de pantalla predeterminado (`wallhaven-5y3571.jpg`).
> - [ ] **Focus Ring:** Las ventanas activas muestran el borde con degradado cian → lavanda reactivo.
> - [ ] **Animaciones:** Las transiciones de espacios de trabajo y apertura de ventanas tienen curvas spring elásticas.
> - [ ] **Cursor:** Se muestra el cursor `MacTahoe-dark-cursors` en todas las aplicaciones Wayland y XWayland.
> - [ ] **Botones Semáforo:** Las apps GTK (Nautilus, Ajustes) muestran botones rojo/amarillo/verde alineados a la izquierda.
> - [ ] **Terminal:** Alacritty inicia directamente con la shell Fish y el prompt temático Material 3.
> - [ ] **Aplicaciones Integradas:**
>   - [ ] `mpv` muestra controles translúcidos estilo Cupertino con uosc.
>   - [ ] `Thunderbird` aplica el tema LiquidBird con blur en la barra lateral.
>   - [ ] `Obsidian` carga con el tema Violet y esquinas curvadas.
> - [ ] **Reactividad Matugen:** Cambiar el wallpaper desde Clavis actualiza automáticamente los colores del focus ring, Fish y Fcitx5.

---

## 6️⃣ Desmantelamiento y Limpieza del Testbench

Una vez certificada la correcta operación, eliminar de forma limpia el usuario de pruebas:

```bash
# 1. Detener procesos y linger del usuario
sudo loginctl disable-linger "$TEST_USER"
sudo pkill -u "$TEST_USER" || true

# 2. Eliminar usuario y su directorio personal
sudo userdel -r "$TEST_USER"

# 3. Eliminar regla de sudoers
sudo rm -f "/etc/sudoers.d/04_${TEST_USER}"

echo "✅ Entorno de pruebas eliminado por completo."
```
