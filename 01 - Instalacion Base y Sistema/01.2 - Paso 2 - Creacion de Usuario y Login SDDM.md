## 🎯 Objetivo

1. Crear un usuario dedicado en el sistema (por defecto: **`niri`**) con su respectivo directorio personal (`/home/niri`), shell `/bin/bash` y asignación al grupo administrativo **`wheel`**.
2. Asignar **paridad total de permisos** con el usuario principal del sistema, incluyendo privilegios de `sudo` sin contraseña y la directiva `verifypw = any` para no bloquear scripts y demonios de mantenimiento.
3. Configurar **SDDM** para que en cada encendido o cierre de sesión presente una interfaz gráfica elegante que permita **elegir interactivamente el usuario** y la **sesión de escritorio** (`Niri` o `Hyprland/Omarchy`).

> [!IMPORTANT]
> **Seguridad:** La contraseña del nuevo usuario no se almacena en este playbook. Debe asignarse de forma interactiva con `passwd <usuario>` tras su creación.

---

## 💡 Decisiones Técnicas y Justificación (Rationale)

### 1. ¿Por qué NO reinstalar SDDM desde cero?
En Arch Linux y Omarchy, SDDM ya está preinstalado y configurado como servicio del sistema (`sddm.service`), operando nativamente sobre Wayland. Reinstalarlo o sustituirlo por otro display manager rompería las integraciones de arranque (Plymouth) y el inicio de servicios. Basta con ajustar su configuración de temas y autologin.

### 2. ¿Por qué deshabilitar `/etc/sddm.conf.d/autologin.conf` moviéndolo de directorio?
Omarchy activa por defecto el inicio de sesión automático hacia el usuario original en la sesión `omarchy.desktop`. Para que el usuario pueda ver la pantalla de bienvenida y seleccionar la cuenta deseada, es indispensable deshabilitar este archivo **sacándolo por completo del directorio** `/etc/sddm.conf.d/`.

> [!WARNING]
> **Comportamiento crítico de SDDM:**
> SDDM analiza **todos** los archivos presentes dentro de `/etc/sddm.conf.d/` sin importar su extensión. Renombrarlo a `autologin.conf.disabled` dentro del mismo directorio **no funciona** y seguirá iniciando sesión automáticamente. La solución infalible es moverlo a un directorio externo como `/etc/sddm.conf.d-disabled/autologin.conf`.

### 3. ¿Por qué cambiar el tema a `catppuccin-sddm-theme-mocha`?
El tema por defecto de Omarchy es ultra-minimalista: contiene únicamente la caja de contraseña para el último usuario logueado, sin controles gráficos para alternar usuario ni menú de sesión Wayland.
* El tema **Catppuccin Mocha** (nativo de Qt 6) provee paneles completos de selección de usuario (`UserField.qml`) y selector de sesión (`SessionPanel.qml`).

### 4. Enlace simblico de sesiones Wayland
Omarchy almacena su entrada de sesión en `/usr/local/share/wayland-sessions/omarchy.desktop`. Al crear un enlace simbólico en `/usr/share/wayland-sessions/`, SDDM lista de forma fiable tanto `Niri` como `Omarchy (Hyprland uwsm)`.

## 🛠️ Ejecución Automatizada (Script Idempotente)

El siguiente script puede ejecutarse directamente en la terminal. El usuario objetivo por defecto es `niri`, pero puede personalizarse pasando una variable de entorno o argumento:

```bash
sudo bash -c '
set -euo pipefail

TARGET_USER="${1:-niri}"

echo "==> 1. Creando usuario $TARGET_USER con grupo wheel..."
if ! id "$TARGET_USER" &>/dev/null; then
    useradd -m -s /bin/bash -G wheel "$TARGET_USER"
    echo "Usuario $TARGET_USER creado. Asigna su contraseña con: passwd $TARGET_USER"
else
    echo "El usuario $TARGET_USER ya existe."
fi

echo "==> 2. Configurando permisos de sudoers para $TARGET_USER..."
cat <<EOF > "/etc/sudoers.d/04_${TARGET_USER}"
${TARGET_USER} ALL=(ALL) NOPASSWD: ALL
Defaults:${TARGET_USER} verifypw = any
EOF
chmod 0440 "/etc/sudoers.d/04_${TARGET_USER}"
visudo -c

echo "==> 3. Enlazando sesiones Wayland para SDDM..."
mkdir -p /usr/share/wayland-sessions
if [[ -f /usr/local/share/wayland-sessions/omarchy.desktop ]]; then
    ln -sf /usr/local/share/wayland-sessions/omarchy.desktop /usr/share/wayland-sessions/omarchy.desktop
fi

echo "==> 4. Instalando tema SDDM Catppuccin Mocha (Qt 6)..."
if ! pacman -Q catppuccin-sddm-theme-mocha &>/dev/null; then
    if command -v yay &>/dev/null; then
        echo "Instalando via yay..."
        # yay como usuario normal con sudo
        sudo -u "${SUDO_USER:-$USER}" yay -S --needed --noconfirm catppuccin-sddm-theme-mocha || true
    fi
    # Si no se encuentra vía paquete, clonar directamente en /usr/share/sddm/themes/
    if [ ! -d "/usr/share/sddm/themes/catppuccin-mocha-mauve" ]; then
        mkdir -p /usr/share/sddm/themes
        git clone --depth 1 https://github.com/catppuccin/sddm.git /tmp/catppuccin-sddm || true
        if [ -d "/tmp/catppuccin-sddm/src/catppuccin-mocha-mauve" ]; then
            cp -r /tmp/catppuccin-sddm/src/catppuccin-mocha-mauve /usr/share/sddm/themes/
        fi
        rm -rf /tmp/catppuccin-sddm
    fi
fi

echo "==> 5. Deshabilitando autologin y fijando tema en SDDM..."
mkdir -p /etc/sddm.conf.d-disabled
# Respaldo de los archivos que se sobrescriben (para poder revertir)
cp -n /etc/sddm.conf.d/10-theme.conf /etc/sddm.conf.d-disabled/10-theme.conf.orig 2>/dev/null || true
cp -n /etc/sddm.conf.d/99-omarchy-login.conf /etc/sddm.conf.d-disabled/99-omarchy-login.conf.orig 2>/dev/null || true
for f in /etc/sddm.conf.d/autologin.conf /etc/sddm.conf.d/autologin.conf.disabled; do
    [[ -f "$f" ]] && mv "$f" /etc/sddm.conf.d-disabled/autologin.conf
done

cat <<EOF > /etc/sddm.conf.d/10-theme.conf
[Theme]
Current=catppuccin-mocha-mauve
EOF

cat <<EOF > /etc/sddm.conf.d/99-omarchy-login.conf
[Theme]
Current=catppuccin-mocha-mauve

[Users]
RememberLastUser=true
RememberLastSession=true
EOF

echo "✅ Paso 2 completado exitosamente para el usuario $TARGET_USER."
' -- "${1:-niri}"
```

## 🔍 Pasos de Verificación y Diagnóstico

> [!CHECKLIST]
> Valida el aprovisionamiento ejecutando los siguientes chequeos:

1. **Grupos del nuevo usuario:**
   ```bash
   id niri
   # Salida esperada: uid=... gid=...(niri) groups=...(niri),...(wheel)
   ```

2. **Privilegios de sudo sin contraseña:**
   ```bash
   sudo -u niri sudo whoami
   # Salida esperada: root
   ```

3. **Sesiones registradas en SDDM:**
   ```bash
   ls -l /usr/share/wayland-sessions/
   # Debe incluir al menos: niri.desktop y omarchy.desktop (o hyprland.desktop)
   # Si Herald OS está instalado, también herald-os.desktop
   ```
   > [!TIP]
   > SDDM lee las sesiones de `/usr/local/share/wayland-sessions` y `/usr/share/wayland-sessions` (`sddm --example-config | grep SessionDir`). Cualquier `.desktop` en esos directorios aparece en el selector del tema Catppuccin sin más configuración. La sesión de Herald OS se documenta en [[01.4 - Sesion Herald OS en SDDM|Sesión Herald OS en SDDM]].

4. **Verificar que autologin está desactivado y el tema fijado:**
   ```bash
   cat /etc/sddm.conf.d/10-theme.conf
   cat /etc/sddm.conf.d/99-omarchy-login.conf
   # Comprobar que no hay directivas de autologin activas:
   grep -rqs "^\[Autologin\]" /etc/sddm.conf.d/ || echo "✅ Autologin desactivado correctamente"
   ```
