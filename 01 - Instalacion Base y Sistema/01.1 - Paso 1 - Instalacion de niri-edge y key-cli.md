## 🎯 Objetivo

Desplegar a nivel de sistema operativo en **Arch Linux / Omarchy** el compositor **`niri-edge`** (fork con minimización nativa) y el runtime CLI **`key-cli`** desde sus ramas principales (`HEAD`), configurando permisos de hardware avanzados:
- Acceso a eventos de teclado (`evdev` para detección de Caps Lock / Num Lock).
- Lectura de telemetría de energía de CPU en tiempo real vía RAPL (`/sys/class/powercap`).
- Integraciones con portapapeles, capturas de pantalla, audio y video Wayland.
- **Aislamiento estricto:** Garantizar que no se modifique ningún archivo en `~/.config/` del usuario que compila.

## 🛠️ Dependencias del Sistema

Instalar las herramientas de compilación y librerías de soporte requeridas vía `pacman`:

```bash
sudo pacman -S --needed --noconfirm \
  rust cargo clang cmake ninja qt6-base base-devel \
  waybar fuzzel alacritty mako swaybg swaylock xwayland-satellite \
  xdg-desktop-portal-gnome polkit-gnome wl-clipboard brightnessctl playerctl \
  cliphist libqalculate python-evdev python-pyudev gpu-screen-recorder slurp ffmpeg libpulse
```

> [!NOTE]
> `pactl` no es un paquete de Arch: el comando lo provee `libpulse`. Incluir `pactl` en la lista hace que `pacman` aborte toda la transacción con `target not found`.

## 🔧 Proceso de Instalación Paso a Paso

### 1. Compilación y Despliegue de `niri-edge`

El siguiente bloque clona, compila en modo optimizado e instala binarios, unidades systemd y autocompletados en el sistema:

```bash
# Definir directorio de trabajo de compilación (configurable).
# /opt/src es también el que usa el script de actualización diaria del Paso 3.
BUILD_DIR="${BUILD_DIR:-/opt/src}"
sudo mkdir -p "$BUILD_DIR"
sudo chown "$USER:$USER" "$BUILD_DIR"

# 1. Clonar o actualizar el repositorio
cd "$BUILD_DIR"
if [ ! -d "niri-edge" ]; then
    git clone -b personal https://github.com/robert-flo/PJ-NIRI-fo-niri-edge.git niri-edge
    git -C niri-edge remote add upstream https://github.com/StatIndet/niri-edge.git
    git -C niri-edge remote set-url --push upstream DISABLE
    cd niri-edge
else
    cd niri-edge
    git switch personal
    git pull --ff-only
fi

# 2. Compilar binario en release (git del sistema para dependencias git, ver nota abajo)
CARGO_NET_GIT_FETCH_WITH_CLI=true cargo build --release

# 3. Desplegar ejecutables en /usr/local/bin y enlaces simblicos
sudo install -Dm755 target/release/niri /usr/local/bin/niri
sudo ln -sf /usr/local/bin/niri /usr/bin/niri

sudo install -Dm755 resources/niri-session /usr/local/bin/niri-session
sudo ln -sf /usr/local/bin/niri-session /usr/bin/niri-session

# 4. Registrar sesión Wayland para Display Managers (SDDM / GDM)
sudo install -Dm644 resources/niri.desktop /usr/share/wayland-sessions/niri.desktop
sudo install -Dm644 resources/niri.desktop /usr/local/share/wayland-sessions/niri.desktop

# 5. Instalar configuración de portales XDG (capturas y screen-sharing)
sudo install -Dm644 resources/niri-portals.conf /usr/share/xdg-desktop-portal/niri-portals.conf
sudo install -Dm644 resources/niri-portals.conf /usr/local/share/xdg-desktop-portal/niri-portals.conf

# 6. Unidades systemd de sesión para usuarios
sudo install -Dm644 resources/niri.service /usr/lib/systemd/user/niri.service
sudo install -Dm644 resources/niri-shutdown.target /usr/lib/systemd/user/niri-shutdown.target

# 7. Autocompletados de shell
sudo mkdir -p /usr/share/bash-completion/completions /usr/share/zsh/site-functions /usr/share/fish/vendor_completions.d
target/release/niri completions bash | sudo tee /usr/share/bash-completion/completions/niri > /dev/null
target/release/niri completions zsh | sudo tee /usr/share/zsh/site-functions/_niri > /dev/null
target/release/niri completions fish | sudo tee /usr/share/fish/vendor_completions.d/niri.fish > /dev/null
sudo chmod 644 /usr/share/bash-completion/completions/niri /usr/share/zsh/site-functions/_niri /usr/share/fish/vendor_completions.d/niri.fish

# 8. Recargar configuraciones de systemd
sudo systemctl --system daemon-reload
```

> [!WARNING]
> **GitHub reescrito a SSH (`url.git@github.com:.insteadOf`).**
> Si tu `~/.config/git/config` reescribe `https://github.com/` a SSH, la librería git interna de cargo solo intenta autenticar con `ssh-agent` y falla al descargar `smithay` (`failed to authenticate when downloading repository`). `CARGO_NET_GIT_FETCH_WITH_CLI=true` hace que cargo use el `git` del sistema, que sí lee tu llave SSH. No modifica tu configuración.

### 2. Instalación de `key-cli` y Capacidades de Hardware

`key-cli` cuenta con su propio instalador (`scripts/install.sh`) que crea un entorno Python virtual aislado en `/usr/local/lib/key-cli/venv/`, compila el monitor nativo en C++ (`key-sysmon`) y el lector de energía (`key-cpu-power`).

```bash
cd "$BUILD_DIR"
if [ ! -d "key-cli" ]; then
    git clone -b personal https://github.com/robert-flo/PJ-NIRI-fo-key-cli.git key-cli
    git -C key-cli remote add upstream https://github.com/StatIndet/key-cli.git
    git -C key-cli remote set-url --push upstream DISABLE
    cd key-cli
else
    cd key-cli
    git switch personal
    git pull --ff-only
fi

# 1. Instalación base (como TU usuario, nunca con sudo: el instalador se eleva solo
#    para desplegar en /usr/local y rechaza ejecutarse como root)
/usr/bin/python3 scripts/installer.py

# 2. HABILITACIÓN 1: Regla udev para eventos de teclado (Caps / Num Lock)
# Instala /etc/udev/rules.d/71-clavis-keyboard-leds.rules y recarga udev
/usr/bin/python3 scripts/installer.py --keyboard enable --acknowledge-keyboard-access --apply

# 3. HABILITACIÓN 2: Lectura de energía CPU (RAPL) sin root
# Otorga permisos cap_dac_read_search al binario nativo
sudo setcap 'cap_dac_read_search=ep' /usr/local/libexec/key-cli/key-cpu-power
```

> [!WARNING]
> **Python de `mise`, `pyenv` o `asdf` en el `PATH`.**
> `scripts/install.sh` ejecuta `python3` del `PATH`. Si es otra versión que la del sistema (por ejemplo, Python 3.15 de `mise` frente a 3.14 de Arch), los paquetes se compilan como `cp315` y el despliegue final, que siempre usa `/usr/bin/python3`, falla con `is not a supported wheel on this platform`. Invocar `/usr/bin/python3 scripts/installer.py` directamente lo evita.

> [!CAUTION]
> **Nunca `sudo /usr/bin/python3 scripts/installer.py`.** El instalador hace dos trabajos: el despliegue de sistema (venv en `/usr/local/lib/key-cli`, `/usr/local/bin/key`, binarios nativos), para el que llama a `sudo` por su cuenta, y la configuración de servicios de usuario (`systemctl --user`), que pertenecen a quien lo ejecuta. Como root, esa segunda parte iría al usuario root, así que se niega:
> ```text
> Installation/configuration failed: Start this tool as your desktop user, without sudo.
> It elevates only deployment; root cannot configure user services.. Earlier completed steps
> may remain; inspect the manifest before retrying.
> ```
> Si te pasa, no hay nada que deshacer a mano: repite el comando **como tu usuario** (sin `sudo`) y después el `setcap`. Por esta misma razón el actualizador diario, que corre como root, instala `key-cli` como el dueño de `/opt/src` (ver [[01.3 - Paso 3 - Clavis Shell y Actualizaciones|Paso 3]]).

> [!IMPORTANT]
> Cada reinstalación de `key-cli` reemplaza `key-cpu-power` y borra su capacidad. Repite el `setcap` después de reinstalar; el script de actualización diaria ya lo hace.

### 3. `key clipboard --daemon` (fork, rama `personal`)

`key-cli` de StatIndet no tiene `key clipboard --daemon`: el subcomando `clipboard` exige una acción (`list`, `watch`, etc.), así que `spawn-at-startup "key" "clipboard" "--daemon"` fallaba en cada inicio. Mi fork lo añade ([PR #1 del fork](https://github.com/robert-flo/PJ-NIRI-fo-key-cli/pull/1), documentado en `docs/protocol.md` como `clipboard.daemon`) con el mismo espíritu que `key shell --daemon`:

| Situación | Qué hace `key clipboard --daemon` |
|---|---|
| Ya hay un watcher con el lock de `$XDG_RUNTIME_DIR/key/clipboard-watch.lock` | Nada; sale con código 0 (`clipboard watcher already running`). |
| Existe `clavis-clipboard.service` y puede arrancar | `systemctl --user start clavis-clipboard.service`; systemd sigue siendo el único dueño del watcher. |
| No hay servicio o no puede arrancar (por ejemplo, fuera de `niri.service`) | Lanza `key clipboard watch` en segundo plano, en su propia sesión. |

El cambio incluye pruebas (la suite completa de 219 pruebas pasa) y llega con el resto de `personal`: el script de actualización diaria solo hace avance rápido sobre la rama seguida. La línea de arranque vive en [robert-flo/niri-dotfiles](https://github.com/robert-flo/niri-dotfiles) (`config.kdl`), así que cualquier usuario restaurado con dotbare la recibe.

> [!WARNING]
> Solo para sesiones **niri**. En Omarchy/Hyprland no lo ejecutes: Omarchy ya tiene su propio capturador (`/usr/share/omarchy/shell/plugins/clipboard/capture.sh`) y como allí no existe `niri.service`, `--daemon` lanzaría un segundo watcher.

Verificación:
```bash
key clipboard --help | head -2          # usage: key clipboard [-h] [--daemon] ...
key clipboard --daemon; key clipboard --daemon
# clipboard watcher started / started clavis-clipboard.service
# clipboard watcher already running
```

## 🔍 Verificación y Pruebas de Calidad

> [!CHECKLIST]
> Ejecuta estas comprobaciones para asegurar que los componentes quedaron correctamente desplegados:

1. **Validar versión y sintaxis de niri:**
   ```bash
   niri --version
   # Debe retornar la versión compilada (ej. niri 26.04)
   
   niri validate --config "$BUILD_DIR/niri-edge/resources/default-config.kdl"
   # Salida esperada: "niri: config is valid"
   ```

2. **Diagnóstico general de `key-cli`:**
   ```bash
   key doctor --json
   ```
   **Criterios de éxito:**
   - `"ok": true`
   - `"missing": []`
   - Todas las características (`shell`, `ipc`, `record`, `audio`, `clipboard-list`, `calculator`, `keyboard`, etc.) en valor `true`.

3. **Verificar acceso a eventos de teclado:**
   ```bash
   key keyboard status --format json
   ```
   - Debe responder: `"available": true` y `"error": null`.

4. **Verificar lectura de telemetría de energía de CPU:**
   ```bash
   key sysmon cpu --format json
   ```
   - El atributo `powerWatts` dentro de `"cpu"` debe arrojar un valor numérico positivo real.

5. **Aislamiento de configuración personal:**
   ```bash
   test ! -d ~/.config/niri && test ! -d ~/.config/key && echo "✅ Aislamiento respetado: El usuario compilador no fue modificado."
   ```
   > [!NOTE]
   > Si el usuario compilador usa la sesión de Herald OS, esta prueba falla a propósito: Herald genera su propia configuración en `~/.config/niri/herald-os.kdl` (y `theme.kdl`, `outputs.kdl`, `local.kdl`). No toca `config.kdl`. Ver [[01.4 - Sesion Herald OS en SDDM|Sesión Herald OS en SDDM]].
