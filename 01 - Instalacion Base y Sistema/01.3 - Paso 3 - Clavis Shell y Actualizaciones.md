## 🎯 Objetivo

1. **Instalar Clavis Shell desde `HEAD`:** Compilar e instalar la suite de shell de escritorio desde la rama `personal` de mi fork [robert-flo/quickshell](https://github.com/robert-flo/quickshell) (sincronizada con [StatIndet/quickshell](https://github.com/StatIndet/quickshell)) con todos sus módulos nativos C++.
2. **Resolver todas las dependencias oficiales, AUR y recursos externos:**
   - Paquetes oficiales: `quickshell` (0.3.1), `qt6-*`, `maplibre-native-qt`, `qtkeychain-qt6`, `libpipewire`, `matugen`, `awww`, etc.
   - Paquetes AUR: `libcava` (biblioteca compartida para visualizador de audio), `qt6-m3shapes-git` (geometría Material 3 para QML), `ttf-lxgw-wenkai-screen`.
   - Recursos meteorológicos: Iconos y animaciones vectoriales `@meteocons/svg` y `@meteocons/lottie`.
3. **Configurar el entorno exclusivo para el usuario objetivo (ej. `niri`):**
   - Estructura modular `~/.config/niri/config.kdl` con autostart de demonios (`key shell`, `key clipboard`, `xwayland-satellite`, `polkit-gnome`).
   - Fragmentos KDL modulares (`binds.kdl`, `layer-rules.kdl`, `effects.kdl`, `cursor.kdl`, `minimize-animation.kdl`, `hot-corners.kdl`).
   - Persistencia de servicios de usuario systemd (`clavis-shell.service`, `clavis-clipboard.service`) mediante `loginctl enable-linger`.
4. **Automatización de mantenimiento diario:** Implementar un script y timer de `systemd` para actualizar automáticamente `niri-edge`, `key-cli`, `quickshell` y paquetes del sistema.

## 💡 Decisiones Técnicas y Arquitectura (Rationale)

### 1. ¿Instalación a Nivel de Sistema vs Nivel de Usuario?
* **Nivel Sistema (Binarios y Módulos Compartidos):**
  Clavis Shell compila plugins nativos en C++ para Qt Quick (`Clavis.Weather`, `Clavis.Cava`, `Clavis.Niri`, `Clavis.WindowPreview`, etc.) que residen en `/usr/lib/qt6/qml/Clavis` y distribuye su configuración base a `/etc/xdg/quickshell/clavis`. Estos componentes deben instalarse a nivel de sistema con permisos de root (`sudo cmake --install`).
* **Nivel Usuario (Aislamiento Total de Dotfiles):**
  Toda la configuración específica del usuario (`~/.config/niri/config.kdl`, fragmentos KDL, temas Matugen locales, servicios systemd) se ejecuta estrictamente bajo la identidad del usuario objetivo con `sudo -u $TARGET_USER -H bash -c '...'`. De este modo no se contamina el usuario principal ni otros usuarios.

### 2. ¿Por qué compilar desde `HEAD` de Git?
Las releases empaquetadas estáticas no contienen parches de estabilidad críticos presentes en `HEAD`:
- Corrección del refresco del modelo de calendario entre días en Qt.
- Corrección de eventos de desbloqueo en Quickshell (evita que el Dock permanezca bloqueado tras salir del lockscreen).
- Eliminación de animaciones espurias de estiramiento en sliders de audio y brillo.

### 3. Dependencias Críticas en AUR
- **`libcava`:** Clavis Shell requiere la biblioteca compartida `libcava.so` (con cabeceras en `/usr/include/cava`) para renderizar el ecualizador en tiempo real a través de PipeWire. El paquete estándar `cava` solo incluye el binario interactivo de consola.
- **`qt6-m3shapes-git`:** Provee tipos QML para renderizado de curvas y morfologías dinámicas Material 3.
- **`ttf-lxgw-wenkai-screen`:** Tipografía de interfaz recomendada por el autor para pantallas de alta densidad.

### Paso 1: Instalación de Dependencias del Sistema y AUR

```bash
# 1. Dependencias oficiales de Arch Linux
sudo pacman -S --needed --noconfirm \
    quickshell qt6-base qt6-declarative qt6-svg qt6-wayland qt6-5compat \
    qt6-lottie qt6-location qt6-positioning maplibre-native-qt qtkeychain-qt6 \
    libpipewire systemd-libs libxkbcommon ttf-material-symbols-variable \
    matugen awww rclone brightnessctl ddcutil \
    imagemagick xdg-terminal-exec networkmanager bluez upower pipewire \
    wireplumber gsettings-desktop-schemas wl-clipboard fd slurp grim \
    gpu-screen-recorder ffmpeg libpulse hyprpicker flatpak \
    qt6-tools vulkan-headers

# 2. JetBrains Mono Nerd Font: solo si no la provee ya otro paquete (Omarchy trae la variante basic)
pacman -Q ttf-jetbrains-mono-nerd-basic &>/dev/null || sudo pacman -S --needed --noconfirm ttf-jetbrains-mono-nerd

# 3. Dependencias desde AUR (usando yay)
yay -S --needed --noconfirm qt6-m3shapes-git libcava ttf-lxgw-wenkai-screen mpvpaper-git dotbare
```

> [!WARNING]
> **Conflicto de fuentes en Omarchy.**
> Omarchy instala `ttf-jetbrains-mono-nerd-basic`, que es dependencia directa del metapaquete `omarchy` y choca con `ttf-jetbrains-mono-nerd`. Reemplazarlo rompería esa dependencia. No hace falta: `-basic` declara `provides=ttf-jetbrains-mono-nerd` e incluye la familia `JetBrainsMono Nerd Font` que pide Clavis.

> [!NOTE]
> **Dependencias de compilación que faltaban:**
> - `qt6-tools`: Clavis exige el componente `LinguistTools` (`find_package(Qt6 ... LinguistTools)`); sin él CMake se detiene con `Failed to find required Qt component "LinguistTools"`.
> - `vulkan-headers`: opcional; elimina el aviso `Could NOT find WrapVulkanHeaders` de Qt.

### Paso 2: Preparación y Compilación de Clavis Shell desde `HEAD`

```bash
BUILD_DIR="${BUILD_DIR:-/opt/src}"
cd "$BUILD_DIR"

if [ ! -d "quickshell" ]; then
    git clone -b personal https://github.com/robert-flo/quickshell.git quickshell
    git -C quickshell remote add upstream https://github.com/StatIndet/quickshell.git
    git -C quickshell remote set-url --push upstream DISABLE
    cd quickshell
else
    cd quickshell
    git switch personal
    git pull --ff-only
fi

# 1. Empaquetar y verificar recursos meteorológicos (Python del sistema, no el de mise/pyenv)
/usr/bin/python3 scripts/release.py bundle-resources --cache /tmp/clavis-cache
/usr/bin/python3 scripts/release.py verify-resources

# 2. Configurar build con CMake y Ninja
cmake -S . -B build -G Ninja \
    -DCMAKE_BUILD_TYPE=Release \
    -DBUILD_TESTING=ON \
    -DCMAKE_INSTALL_PREFIX=/usr \
    -DCMAKE_INSTALL_LIBDIR=lib \
    -DCLAVIS_CONFIG_INSTALL_DIR=/etc/xdg/quickshell/clavis \
    -DPython3_EXECUTABLE=/usr/bin/python3

# 3. Compilar todos los módulos nativos
cmake --build build

# 4. Validar suite de pruebas (27 contratos)
ctest --test-dir build --output-on-failure

# 5. Instalar en el sistema
sudo cmake --install build
```

> [!NOTE]
> El directorio `build/` guarda rutas absolutas. Si mueves el repositorio (por ejemplo de `~/src` a `/opt/src`), borra `build/` y vuelve a configurar; si no, Ninja falla con `rebuilding 'build.ninja': subcommand failed`.

### Paso 3: Configuración del Entorno para el Usuario Objetivo

> [!IMPORTANT]
> **Con dotfiles, este paso lo sustituye dotbare.** Los usuarios `niri` y `sura` reciben `config.kdl`, los fragmentos de Clavis y el arranque de `key clipboard --daemon` desde [robert-flo/niri-dotfiles](https://github.com/robert-flo/niri-dotfiles), y el postinstall habilita los servicios (ver [[03.1 - Dotfiles con dotbare|Dotfiles con dotbare]]). De este bloque solo hacen falta los puntos 5 y 6 (grupos y linger). El bloque completo queda para un usuario nuevo sin dotfiles.

El siguiente bloque configura el entorno Wayland bajo el usuario especificado (`TARGET_USER`, por defecto `niri`):

```bash
TARGET_USER="${1:-niri}"
TARGET_HOME="$(getent passwd "$TARGET_USER" | cut -d: -f6)"
TARGET_UID="$(id -u "$TARGET_USER")"

echo "==> Configurando entorno para: $TARGET_USER ($TARGET_HOME, UID: $TARGET_UID)"

# 1. Estructura de directorios y configuración base
sudo mkdir -p "$TARGET_HOME/.config/niri/clavis"
if [ -f "$BUILD_DIR/niri-edge/resources/default-config.kdl" ]; then
    sudo cp "$BUILD_DIR/niri-edge/resources/default-config.kdl" "$TARGET_HOME/.config/niri/config.kdl"
elif [ -f "/usr/share/doc/niri/default-config.kdl" ]; then
    sudo cp "/usr/share/doc/niri/default-config.kdl" "$TARGET_HOME/.config/niri/config.kdl"
fi
sudo chown -R "$TARGET_USER:$TARGET_USER" "$TARGET_HOME/.config/niri"

# 2. Ajustar autostart en config.kdl (Clavis Shell lo arranca clavis-shell.service, ver nota)
sudo /usr/bin/python3 -c "
path = '$TARGET_HOME/.config/niri/config.kdl'
with open(path, 'r') as f:
    c = f.read()
old = 'spawn-at-startup \"waybar\"'
new = '''spawn-at-startup \"xwayland-satellite\"
spawn-at-startup \"/usr/lib/polkit-gnome/polkit-gnome-authentication-agent-1\"
spawn-at-startup \"key\" \"clipboard\" \"--daemon\"'''
if old in c:
    c = c.replace(old, new)
    with open(path, 'w') as f:
        f.write(c)
"

# 3. Generar y vincular fragmentos modulares de Clavis Shell
for feature in binds layer-rules effects cursor minimize-animation hot-corners; do
    sudo -u "$TARGET_USER" -H python3 /etc/xdg/quickshell/clavis/scripts/system/niri_config.py \
        "{\"operation\": \"setup\", \"feature\": \"$feature\"}"
done

# 4. Validar sintaxis de configuración generada
sudo -u "$TARGET_USER" -H niri validate -c "$TARGET_HOME/.config/niri/config.kdl"

# 5. Agregar usuario a grupos de hardware
sudo usermod -a -G input,video,audio "$TARGET_USER"

# 6. Habilitar linger y servicios de sesión de systemd
sudo loginctl enable-linger "$TARGET_USER"
sudo -u "$TARGET_USER" -H XDG_RUNTIME_DIR="/run/user/$TARGET_UID" systemctl --user daemon-reload
sudo -u "$TARGET_USER" -H XDG_RUNTIME_DIR="/run/user/$TARGET_UID" systemctl --user enable \
    clavis-shell.service clavis-clipboard.service
```

> [!IMPORTANT]
> **Arranque de Clavis: los servicios systemd mandan.**
> `clavis-shell.service` y `clavis-clipboard.service` llevan `WantedBy=niri.service`, así que arrancan solos cuando la sesión Niri (vía `niri-session`) inicia `niri.service`.
> - **`key shell --daemon` no va en `config.kdl`:** arrancaría una segunda instancia de Clavis junto al servicio.
> - **`key clipboard --daemon` sí va:** con `key-cli` de mi fork ([[01.1 - Paso 1 - Instalacion de niri-edge y key-cli|Paso 1, sección 3]]) delega en `clavis-clipboard.service` y no hace nada si ya hay un watcher. Así el portapapeles queda garantizado aunque el servicio no esté habilitado, sin duplicarse.

## 🔄 Procedimiento de Actualizaciones Diarias

Para mantener el sistema al día con la rama `personal` de cada fork (que a su vez se sincroniza con StatIndet), se implementa el script centralizado. Copia exacta en `assets/system/usr/local/bin/update-niri-desktop.sh` (ver [[05.4 - Archivos de Sistema de Referencia|Archivos de Sistema de Referencia]]):

### Script `/usr/local/bin/update-niri-desktop.sh`

```bash
#!/usr/bin/env bash
set -euo pipefail

# Directorio donde se encuentran los repositorios clonados.
# Cada repo sigue la rama `personal` de su fork (origin); StatIndet es `upstream`, solo lectura.
SRC_DIR="${SRC_DIR:-/opt/src}"

# Compilar como el dueño de las fuentes; root solo instala.
BUILD_USER="${BUILD_USER:-$(stat -c %U "$SRC_DIR")}"
BUILD_HOME="$(getent passwd "$BUILD_USER" | cut -d: -f6)"

as_builder() {
    runuser -u "$BUILD_USER" -- env -i \
        HOME="$BUILD_HOME" USER="$BUILD_USER" LOGNAME="$BUILD_USER" \
        PATH=/usr/local/bin:/usr/bin:/bin \
        CARGO_NET_GIT_FETCH_WITH_CLI=true \
        bash -c "$1"
}

echo "================================================================"
echo "  Actualizando Niri Desktop desde los forks (rama personal)       "
echo "================================================================"

# 1. Actualizar niri-edge
if [ -d "$SRC_DIR/niri-edge" ]; then
    echo ">> [1/4] Actualizando niri-edge..."
    as_builder "cd '$SRC_DIR/niri-edge' && git fetch origin && { git merge --ff-only '@{u}' || echo 'Advertencia: avance rápido no posible; se compila la versión local'; } && cargo build --release"
    install -Dm755 "$SRC_DIR/niri-edge/target/release/niri" /usr/local/bin/niri
fi

# 2. Actualizar key-cli
if [ -d "$SRC_DIR/key-cli" ]; then
    echo ">> [2/4] Actualizando key-cli..."
    as_builder "cd '$SRC_DIR/key-cli' && git fetch origin && { git merge --ff-only '@{u}' || echo 'Advertencia: avance rápido no posible; se compila la versión local'; } && /usr/bin/python3 scripts/installer.py"
    as_builder "cd '$SRC_DIR/key-cli' && /usr/bin/python3 scripts/installer.py --keyboard enable --acknowledge-keyboard-access --apply"
    setcap 'cap_dac_read_search=ep' /usr/local/libexec/key-cli/key-cpu-power
    if [ -f "$SRC_DIR/key-cli/completions/key.fish" ]; then
        install -Dm644 "$SRC_DIR/key-cli/completions/key.fish" /usr/share/fish/vendor_completions.d/key.fish
    fi
fi

# 3. Actualizar quickshell (Clavis Shell)
if [ -d "$SRC_DIR/quickshell" ]; then
    echo ">> [3/5] Actualizando Clavis Shell..."
    as_builder "cd '$SRC_DIR/quickshell' && git fetch origin && { git merge --ff-only '@{u}' || echo 'Advertencia: avance rápido no posible; se compila la versión local'; } \
        && { /usr/bin/python3 scripts/release.py bundle-resources --cache /tmp/clavis-cache || true; } \
        && cmake -S . -B build -G Ninja \
            -DCMAKE_BUILD_TYPE=Release \
            -DBUILD_TESTING=OFF \
            -DCMAKE_INSTALL_PREFIX=/usr \
            -DCMAKE_INSTALL_LIBDIR=lib \
            -DCLAVIS_CONFIG_INSTALL_DIR=/etc/xdg/quickshell/clavis \
            -DPython3_EXECUTABLE=/usr/bin/python3 \
        && cmake --build build"
    cmake --install "$SRC_DIR/quickshell/build"
fi

# 4. Actualizar clavis-fish-theme
if [ -d "$SRC_DIR/clavis-fish-theme" ]; then
    echo ">> [4/5] Actualizando clavis-fish-theme..."
    as_builder "cd '$SRC_DIR/clavis-fish-theme' && git fetch origin && { git merge --ff-only '@{u}' || echo 'Advertencia: avance rápido no posible; se compila la versión local'; } && cargo build --release --locked"
    install -Dm755 "$SRC_DIR/clavis-fish-theme/target/release/clavis-fish-theme" /usr/local/bin/clavis-fish-theme
fi

# 5. Actualizar paquetes del sistema
echo ">> [5/5] Verificando paquetes del sistema..."
pacman -Syu --needed --noconfirm

echo "================================================================"
echo "  Actualización completada exitosamente.                        "
echo "================================================================"
```

> [!TIP]
> Instálalo desde el vault (queda ejecutable):
> ```bash
> sudo install -Dm755 "<ruta-del-vault>/assets/system/usr/local/bin/update-niri-desktop.sh" /usr/local/bin/update-niri-desktop.sh
> ```

> [!WARNING]
> **Por qué el script compila como el dueño de `/opt/src` y no como root:**
> - El timer lo ejecuta como root. `git` como root rechaza repositorios de otro usuario (`dubious ownership`).
> - El instalador de `key-cli` se niega a correr como root (`Start this tool as your desktop user, without sudo`).
> - Compilar como root dejaría archivos de root en `target/` y `build/`, y las compilaciones manuales posteriores fallarían.
>
> Por eso `as_builder` compila con `runuser` como el dueño de `$SRC_DIR`, y root solo ejecuta `install`, `setcap`, `cmake --install` y `pacman`. La opción `install.sh --all` de la versión anterior no existe en `key-cli`.
> - `git merge --ff-only '@{u}'` avanza cada repo sobre la rama que sigue (`origin/personal` del fork). Ya no hay parches locales que rebasar: los cambios propios viven en `personal`.

### Automatización mediante Systemd Timer (Opcional)

Para ejecutar la actualización diaria a las 04:00 AM:

1. **Crear `/etc/systemd/system/niri-update.service`:**
   ```ini
   [Unit]
   Description=Actualización Diaria Niri Desktop y Clavis Shell
   After=network-online.target

   [Service]
   Type=oneshot
   ExecStart=/usr/local/bin/update-niri-desktop.sh
   ```

2. **Crear `/etc/systemd/system/niri-update.timer`:**
   ```ini
   [Unit]
   Description=Timer para Actualización Diaria Niri Desktop

   [Timer]
   OnCalendar=*-*-* 04:00:00
   Persistent=true

   [Install]
   WantedBy=timers.target
   ```

3. **Habilitar el timer** (o instalar ambas unidades desde `assets/system/etc/systemd/system/` con `sudo install -m644`):
   ```bash
   sudo systemctl daemon-reload
   sudo systemctl enable --now niri-update.timer
   ```
